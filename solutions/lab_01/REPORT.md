## Задание 1. От исходного кода к байткоду

### Часть 1. Режимы запуска

В REPL выражение `2 + 3 * 4` автоматически выводит результат `14`, потому что REPL (Read-Eval-Print Loop) работает в цикле «прочитать → вычислить → **напечатать**». Каждое выражение, возвращающее значение, отличное от `None`, автоматически отображается в консоли.

При запуске файла (`python task_1.py`) интерпретатор работает в скриптовом режиме: результат вычисления выражения просто отбрасывается, если он не передан в `print()` или не присвоен переменной. Чтобы увидеть результат, нужно явно использовать `print(2 + 3 * 4)`.

### Часть 2. Выражения и инструкции

Код:
```python
course = "Python"
hours = 4 * 2
print(f"{course}: {hours} часов")
```

**Выражения:**
- `"Python"` — строковый литерал
- `4 * 2` — арифметическое выражение
- `f"{course}: {hours} часов"` — f-строка (выражение)
- `2 + 3 * 4` — арифметическое выражение

**Инструкции (statements):**
- `course = "Python"` — инструкция присваивания
- `hours = 4 * 2` — инструкция присваивания
- `print(f"{course}: {hours} часов")` — инструкция-выражение (вызов функции)
- `print(2 + 3 * 4)` — инструкция-выражение

**Литералы:**
- `2`, `3`, `4` — целочисленные литералы (int)
- `"Python"` — строковый литерал (str)
- `": "`, `" часов"` — части f-строки (str)

**Имена, создаваемые при выполнении:**
- `course` — связывается с объектом `"Python"` (str)
- `hours` — связывается с объектом `8` (int)

### Часть 3. AST и байткод

#### AST (Abstract Syntax Tree)

Фрагмент AST:
```
Module(
   body=[
      Expr(
         value=Call(
            func=Name(id='print', ctx=Load()),
            args=[
               BinOp(
                  left=Constant(value=2),
                  op=Add(),
                  right=BinOp(
                     left=Constant(value=3),
                     op=Mult(),
                     right=Constant(value=4)))],
            keywords=[])),
      Assign(
         targets=[Name(id='course', ctx=Store())],
         value=Constant(value='Python')),
      Assign(
         targets=[Name(id='hours', ctx=Store())],
         value=BinOp(left=Constant(value=4), op=Mult(), right=Constant(value=2))),
      Expr(
         value=Call(
            func=Name(id='print', ctx=Load()),
            args=[JoinedStr(...)],
            keywords=[]))],
   type_ignores=[])
```

- **Присваивание:** узлы `Assign` — `course = "Python"` и `hours = 4 * 2`
- **Арифметическая операция:** узлы `BinOp` — `2 + 3 * 4` (Add и Mult) и `4 * 2` (Mult)
- **Вызов print():** узлы `Call` с `func=Name(id='print')`

#### Байткод (dis)

```
 11           0 LOAD_NAME                0 (print)
              2 LOAD_CONST               0 (14)
              4 CALL_FUNCTION            1
              6 POP_TOP

 14           8 LOAD_CONST               1 ('Python')
             10 STORE_NAME               1 (course)

 15          12 LOAD_CONST               2 (8)
             14 STORE_NAME               2 (hours)

 16          16 LOAD_NAME                0 (print)
             ...
             32 CALL_FUNCTION            1
             34 POP_TOP
             36 LOAD_CONST               5 (None)

```

- **Загрузка константы:** `LOAD_CONST 0 (14)` — компилятор вычислил `2 + 3 * 4 = 14` на этапе компиляции (constant folding) и загружает уже готовое значение.
- **Вызов функции:** `CALL_FUNCTION 1` — вызывает функцию (print) с одним аргументом.
- **Сохранение имени:** `STORE_NAME 1 (course)` — связывает имя `course` с объектом на вершине стека.

### Контрольный вопрос

**Почему байткод CPython нельзя считать машинным кодом процессора?**

Байткод — это инструкции для виртуальной машины CPython, а не для процессора. Процессор их напрямую не понимает — их выполняет PVM, написанная на C.

## Задание 2. Имена, объекты и сравнение

### Прогнозы и результаты

| Выражение       | Прогноз | Результат | Совпадение |
|-----------------|---------|-----------|------------|
| `a == b`        | True    | True      | ✅          |
| `a is b`        | True    | True      | ✅          |
| `a == c`        | True    | True      | ✅          |
| `a is c`        | False   | False     | ✅          |

### Схема связей имен и объектов

```
Имена:          Объекты в памяти:

  a ──────────┐
              ├──→ [ int: 1000 ] (id: 4336922160)
  b ──────────┘

  c ──────────────→ [ int: 1000 ] (id: 4336922480)
```

- `b = a` не копирует объект, а создает второе имя, указывающее на тот же объект. Поэтому `id(a) == id(b)` и `a is b == True`.
- `c = int("1000")` создает новый объект `int` с тем же значением 1000, но с другим `id`. Поэтому `a == c` (значения равны), но `a is c == False` (разные объекты).

### Проверка None

```python
c = None
print("c is None:", c is None)  # True
```

`None` — синглтон (в программе существует ровно один объект `None`). Проверку на `None` принято выполнять через `is`, а не `==`.

### Интернирование строк

```python
first = "python"
second = "py" + "thon"
print(first == second)   # True
print(first is second)   # True
```

Результат `first is second == True` объясняется тем, что CPython на этапе компиляции выполняет **constant folding**: выражение `"py" + "thon"` вычисляется и превращается в `"python"`. Затем строка `"python"` **интернируется** — хранится в единственном экземпляре. Но полагаться на это в программной логике нельзя, так как это деталь реализации.

### Правило: когда `==`, а когда `is`

- `==` — сравнение **значений** объектов. Используется в подавляющем большинстве случаев.
- `is` — сравнение **идентичности** (один и тот же объект в памяти). Используется только для проверки на `None`, `True`, `False` и в редких случаях, когда важна именно идентичность объекта.

### Контрольные вопросы

1. **Создает ли `b = a` копию объекта?** Нет. `b` просто ссылается на тот же объект, что и `a`.

2. **Что возвращают `type()` и `id()`?** `type()` — тип объекта, `id()` — уникальный идентификатор объекта в памяти.

3. **Почему `None` сравнивают через `is`?** `None` — единственный объект своего типа (синглтон), поэтому проверка `is None` точнее и быстрее.

## Задание 3. Числовые типы, операции и преобразования

### Эксперимент A. int и арифметические операторы

| Операция | Результат | Тип    |
|----------|-----------|--------|
| `x + y`  | 22        | int    |
| `x - y`  | 12        | int    |
| `x * y`  | 85        | int    |
| `x / y`  | 3.4       | float  |
| `x // y` | 3         | int    |
| `x % y`  | 2         | int    |
| `x ** y` | 1419857   | int    |

Оператор `/` (обычное деление) **всегда** возвращает `float`, даже если результат — целое число (например, `10 / 2 == 5.0`). Это сделано для единообразия и предотвращения ошибок. Оператор `//` (целочисленное деление) возвращает `int` при делении двух `int`, отбрасывая дробную часть.

### Эксперимент B. Большие целые числа

`2 ** 1000` — число из 302 цифр. Тип: `int`.

В Python целые числа имеют **произвольную точность** (arbitrary precision). В отличие от C/Java, где `int` ограничен 32 или 64 битами, Python автоматически выделяет необходимое количество памяти для хранения числа любого размера. Переполнение невозможно.

### Эксперимент C. float

```
0.1 + 0.2 = 0.30000000000000004
result == 0.3: False
result - 0.3 = 5.551115123125783e-17
math.isclose(result, 0.3): True
```

Числа `0.1` и `0.2` не представимы точно в двоичной системе (стандарт IEEE 754). Их сумма содержит крошечную погрешность (~5.5 × 10⁻¹⁷). Поэтому прямое сравнение `result == 0.3` дает `False`.

**Правило безопасного сравнения float:** использовать `math.isclose(a, b)` или сравнивать `abs(a - b) < epsilon`, где `epsilon` — допустимая погрешность.

### Эксперимент D. bool, complex и преобразование типов

| Выражение       | Результат | Тип     |
|-----------------|-----------|---------|
| `int("42")`     | 42        | int     |
| `float("3.14")` | 3.14      | float   |
| `str(2026)`     | '2026'    | str     |
| `bool(0)`       | False     | bool    |
| `bool(-1)`      | True      | bool    |
| `bool("")`      | False     | bool    |
| `bool("False")` | True      | bool    |
| `complex(2,-3)` | (2-3j)    | complex |

**Почему `bool("False")` == `True`?** Функция `bool()` для строк проверяет не содержимое строки, а является ли она непустой. Строка `"False"` содержит 5 символов → она непустая → `True`. Пустая строка `""` — единственная «ложная» строка.

**Falsy-значения из эксперимента D:** `0` (целое число ноль) и `""` (пустая строка).

Комплексное число `(2-3j)`: действительная часть = `2.0`, мнимая часть = `-3.0`.

### Контрольные вопросы

1. **Почему `int / int` → `float`?** Оператор `/` в Python 3 всегда возвращает `float`, чтобы `7 / 2` давало `3.5`, а не `3`.

2. **Отличие `int("42")` от `int(42.9)`?** `int("42")` разбирает строку в число. `int(42.9)` отбрасывает дробную часть (не округляет).

3. **Falsy-значения:** `0` и `""` (пустая строка).

Три способа форматирования дали одинаковый результат:
```
Анна Смирнова — Основы программирования на Python: 7/10 (70.0%)
```

Unicode-эксперимент:
```
Символ: Я
Кодовая позиция (ord): 1071
Восстановленный символ (chr): Я
Байтовое представление (UTF-8): b'\xd0\xaf'
Длина в байтах: 2
```

Ошибка при попытке изменить символ:
```python
student[0] = "О"  # TypeError: 'str' object does not support item assignment
```
Строки в Python **неизменяемы** (immutable). Нельзя изменить отдельный символ по индексу.

### Контрольные вопросы

1. **Почему `len(symbol)` и `len(symbol.encode("utf-8"))` различаются?**
   `len()` для строки считает символы (1), а для байтов — байты (2, т.к. кириллица в UTF-8 занимает 2 байта).

2. **Что означают `start`, `stop`, `step` в `text[start:stop:step]`?**
   `start` — начало (включительно), `stop` — конец (не включительно), `step` — шаг. При `step = -1` строка идёт в обратном порядке.

3. **Почему строка неизменяема, если `.upper()` возвращает «измененный» текст?**
   `.upper()` не меняет исходную строку, а создаёт новую. Оригинал остаётся прежним.

### Разбор арифметической строки

```python
total_seconds = runs * duration
```

- **Имена:** `total_seconds` (целевое имя), `runs`, `duration` (операнды)
- **Оператор:** `*` (умножение)
- **Литералов нет** — все значения берутся из ранее связанных имен
- `runs` (int) × `duration` (float) → результат `float` (автоматическое приведение типов)

### Путь программы

1. **Исходный файл** (`task_5.py`) — текст на языке Python.
2. **Разбор исходного текста** (lexer/parser) — исходный текст разбивается на токены, затем строится дерево разбора.
3. **AST** (Abstract Syntax Tree) — абстрактное синтаксическое дерево, очищенное от синтаксического «шума».
4. **Компиляция в байткод** — компилятор CPython транслирует AST в последовательность инструкций байткода (`.pyc`-файл).
5. **Выполнение виртуальной машиной CPython (PVM)** — PVM последовательно исполняет инструкции байткода, управляя стеком, именами и объектами.

### Почему `input()` нужно явно преобразовывать

Функция `input()` **всегда** возвращает строку (`str`), независимо от того, что ввёл пользователь. Если пользователь ввел `"42"`, результат — строка `"42"`, а не число `42`. Для арифметических операций необходимо явное преобразование: `int("42")` или `float("12.5")`. Без преобразования оператор `*` для строки означает повторение (`"42" * 3 == "424242"`), а не умножение.

### Контрольный вопрос

**Что изменится на уровне объектов при повторном присваивании?**

Имя перепривязывается к новому объекту. Старый объект удаляется сборщиком мусора, если на него больше никто не ссылается.

## Вывод

Три наиболее неожиданные особенности Python:

1. **Произвольная точность целых чисел.** В отличие от большинства языков, `int` в Python не ограничен фиксированным количеством бит и может хранить сколь угодно большие числа без переполнения.

2. **`0.1 + 0.2 ≠ 0.3`.** Погрешности IEEE 754 существуют во всех языках, но в Python это особенно заметно из-за прямого сравнения `==`. Использование `math.isclose()` — обязательная практика.

3. **`bool("False") == True`.** Интуитивно кажется, что строка `"False"` должна быть ложной, но `bool()` проверяет лишь непустоту строки, а не её содержание. Это важный момент при обработке пользовательского ввода.
